# 2026dsa_finalproject_group_11
Project Workflow and Team Collaboration

After receiving the project, we had an initial discussion on how to structure our workflow. To ensure that both team members were fully engaged and able to independently develop their own ideas, we decided that each of us would complete the entire pipeline individually. This includes data wrangling, feature engineering, model development using XGBoost, as well as implementing a second machine learning model.

Throughout the process, we continuously communicated to exchange ideas, compare intermediate results, and discuss different modeling strategies. This allowed us to explore multiple perspectives rather than converging too early on a single approach.

In the end, we compared all four models generated from our independent workflows. The final model was selected based on performance metrics, specifically RMSE and R². The best-performing model was then used for final submission and deployment in the Shiny app.

As a result of this design, you will see that each of us has pushed multiple code files, typically ranging from three to five. To maintain a clean and professional structure, we created a new GitHub repository and only uopload the code required based on the instruction. (We did not push the csv files with wrangled data. But if you need that, please let us know.)

From the code, it is clear that we followed different approaches and modeling ideas, which we consider to be a valuable and intentional part of this project.
